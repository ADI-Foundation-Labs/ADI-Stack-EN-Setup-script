# Upgrading External Node from v0.10.0 to v0.17.1

## Overview

This guide covers the upgrade process from External Node v0.10.0 to v0.17.1. This upgrade introduces new mandatory configuration for network identity and peer discovery.

## Major Changes in v0.17.1

### Network Identity and Peer Discovery

Version v0.17.1 introduces mandatory requirements for node identity and peer discovery:

1.  **`EXTERNAL_NETWORK_SECRET_KEY`**: A private key used to identify and authenticate your external node in the network.
2.  **`BOOT_NODE_URLS`**: A list of boot nodes used for peer discovery.

These parameters are now required for the node to start and function correctly within the P2P network.

## Prerequisites

Before starting the upgrade:

- [ ] **Backup**: Ensure you have backups of any custom configurations.
- [ ] **Network Info**: Obtain the list of boot nodes from the ADI team.
- [ ] **Tools**: Ensure you have `openssl` (for key generation) and `cast` (optional, for public key derivation) installed.

## Upgrade Steps

### Step 1: Pull Latest Changes

Pull the latest changes from the repository to ensure you have the most recent version of the setup script and configurations:

```bash
git pull origin main
```

### Step 2: Generate Network Secret Key

If you don't have one already, generate a secure random private key for your node:

```bash
openssl rand -hex 32
```

Save this key securely. You will need it to start the node.

### Step 3: Stop All Services

Stop the running containers:

```bash
./external-node.sh down
```

### Step 4: Pull Latest External Node Image

Pull the updated v0.17.1 container image:

```bash
./external-node.sh pull
```

### Step 5: Start the External Node with New Configuration

You must now provide the `BOOT_NODE_URLS` and `EXTERNAL_NETWORK_SECRET_KEY` in addition to the `GENERAL_L1_RPC_URL`.

#### Option A: Using Environment Variables

```bash
export GENERAL_L1_RPC_URL="https://your-l1-endpoint"
export BOOT_NODE_URLS="enode://{pubkey}@{ip}:{port}"
export EXTERNAL_NETWORK_SECRET_KEY="{your-generated-key}"

./external-node.sh start
```

#### Option B: Using Command Line Arguments

```bash
./external-node.sh start \
  --l1-rpc-url https://your-l1-endpoint \
  --boot-node-urls "enode://{pubkey}@{ip}:{port}" \
  --external-network-secret-key {your-generated-key}
```

### Step 6: Monitor Logs and Verify

Monitor the logs to ensure the node connects to peers and starts syncing:

```bash
./external-node.sh logs
```

Check the node health:

```bash
curl http://localhost:3071/health
```
