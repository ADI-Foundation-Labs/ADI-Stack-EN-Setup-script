# External Node: v0.20.12 → v0.24.2

> **🚧 Status:** This upgrade has been applied to **testnet and mainnet** (`docker-compose.testnet.yml`, `docker-compose.mainnet.yml`). The examples below use the `--testnet` flag — adjust the network flag to match whichever network you're actually upgrading.

## Upgrade Order

**Upgrade your external node before the main node.** ADI announces an EN deadline that comes before the main-node upgrade window. Upgrade your node before that deadline.

- A v0.24.2 main node writes blocks with `execution_version: 0`. A v0.20.12 external node can't process these blocks: it panics with `Unsupported ZKsync OS execution version` and crash-loops.
- A v0.24.2 external node follows the current main node (v0.21) without problems, and P2P works in both directions. So upgrading early is safe.

> [!CAUTION]
> **There is no rollback.** After your node stores blocks from a v0.24.2 main node, it can't go back to v0.20.12. Keep your node on v0.24.2.

## Image Change

The image moves to a new public path:

| Version      | Image                                                                |
|--------------|----------------------------------------------------------------------|
| v0.20.12-b1  | `harbor.sde.adifoundation.ai/ghpc/adi-foundation-labs/server`        |
| v0.24.2-b7   | `harbor.sde.adifoundation.ai/adi-public/chain/server`                |

The image is public, so `pull` needs no registry login.

- If you set `EN_VERSION`, unset it or set it to `v0.24.2-b7`. `EN_VERSION` sets only the tag, and the new path has no `v0.20.12-b1` tag.
- If you run your own docker-compose file, update both the image path and the tag.

## Removed Variables

| Variable       | Notes                                                                                                                   |
|----------------|-------------------------------------------------------------------------------------------------------------------------|
| `network_host` | Never a real config key — the node ignored it. The real key is `network_address`, and its default `0.0.0.0` is correct. |

No new variables are required. All other variables in the docker-compose files are unchanged.

## Changed Defaults

| Variable                                  | v0.20.12 default | v0.24.2 default | Notes                                                       |
|-------------------------------------------|------------------|-----------------|-------------------------------------------------------------|
| `rpc_max_batch_size`                      | no limit         | **`1000`**      | JSON-RPC batches with more than 1000 requests are rejected. |
| `sequencer_en_replay_inactivity_timeout`  | —                | **`300s`**      | New key.                                                    |
| `l1_provider_request_timeout`             | —                | **`30s`**       | New key.                                                    |

## API and Metrics Changes

- `zks_getBlockMetadataByNumber` no longer returns the `executionVersion` field.
- The Prometheus metric `execution_last_execution_version` is now `execution_last_protocol_version`. Update your dashboards and alerts.

## Other Changes

**Storage** — no DB migration and no resync. Your existing data directory works as it is.

**Memory** — the RocksDB block caches now use up to about 5 GiB in total. If your container has a memory limit, check that it leaves room for this.

**L1 load** — a new interop-roots watcher also runs on external nodes. It reads logs from your L1 RPC. Expect more L1 requests than before, mostly on the first start.

**Next chain upgrade** — v0.24.2-b7 is required for the next chain upgrade, which turns on EIP-7702. After that chain upgrade lands, restart your external node (see [Restart After the Next Chain Upgrade](#restart-after-the-next-chain-upgrade)). ADI announces the restart time separately.

**Ports and genesis** — unchanged. Ports `3050`, `3060` TCP+UDP, `3071`, and `3312` stay the same, and the current `genesis/` files stay valid.

## Upgrade Steps

### 1. Check the EN Deadline

Find the EN deadline in the ADI announcement (see [Upgrade Order](#upgrade-order)).

### 2. Find Your Network Secret Key

Step 6 starts the node with your saved key, so it keeps the same P2P identity. If you let the script generate the key and didn't save it, read it from the running container before you stop it:

```bash
# Container name: adi_<network>_external_node, or ${CONTAINER_PREFIX}_external_node if you set CONTAINER_PREFIX
docker inspect adi_testnet_external_node \
  --format '{{range .Config.Env}}{{println .}}{{end}}' | grep network_secret_key
```

If you start without a key, the script generates a new one, and your node gets a new P2P identity.

### 3. Pull Latest Repository Changes

```bash
git pull origin main
```

This updates the docker-compose file for the network you're upgrading with the v0.24.2 image.

### 4. Update Your Own Config (if any)

- Unset `EN_VERSION`, or set it to `v0.24.2-b7`. If you run your own docker-compose file, update the image path and tag (see [Image Change](#image-change)).
- Delete `network_host` from your own config.
- Check that your container memory limit leaves room for about 5 GiB of RocksDB block caches.
- Update dashboards and alerts to use `execution_last_protocol_version`.

### 5. Pull the New Docker Image

```bash
./external-node.sh --testnet pull
```

### 6. Restart the External Node

Stop the node:

```bash
./external-node.sh --testnet down
./external-node.sh --testnet status    # confirm all stopped
```

Start it with your saved key:

```bash
./external-node.sh --testnet start \
  --l1-rpc-url https://your-l1-endpoint \
  --external-network-secret-key <saved-key>
```

Or export it as an environment variable before running the script:

```bash
export EXTERNAL_NETWORK_SECRET_KEY="<saved-key>"
./external-node.sh --testnet start --l1-rpc-url https://your-l1-endpoint
```

### 7. Verify Sync

```bash
./external-node.sh --testnet logs
```

Look for:
```
en_connection{peer_id=0x…}: … requesting block replays from main node next_block=N   ← connected to the boot node
Received replay block command from main node: block_number: N                        ← syncing
persisted block block_number=N                                                       ← blocks stored
```

`next_block` must continue from the block your node had before the upgrade — your node keeps its data.

Should NOT see:
```
panicked at
```

Health check:

```bash
curl http://localhost:3071/status/health
```

Block number parity with main node:

```bash
# Your EN
curl -s -X POST http://localhost:3050 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'

# Main node reference (testnet; on mainnet use https://rpc.adifoundation.ai)
curl -s -X POST https://rpc.ab.testnet.adifoundation.ai \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'
```

### Restart After the Next Chain Upgrade

When ADI announces the restart time, restart the node with the same commands as in step 6:

```bash
./external-node.sh --testnet down
./external-node.sh --testnet start \
  --l1-rpc-url https://your-l1-endpoint \
  --external-network-secret-key <saved-key>
```
