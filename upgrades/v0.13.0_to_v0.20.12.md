# External Node: v0.13.0 → v0.20.12

> **🚧 Status:** This upgrade has been applied to **mainnet, testnet, and devnet** (`docker-compose.mainnet.yml`, `docker-compose.testnet.yml`, `docker-compose.devnet.yml`). The examples below run bare (no network flag), which targets mainnet — adjust the network flag (`--testnet`/`--devnet`) to match whichever network you're actually upgrading.

## Removed Variables

| Variable                                        | Notes                                               |
|-------------------------------------------------|-----------------------------------------------------|
| `sequencer_block_replay_download_address`       | HTTP replay removed, replaced by P2P                |
| `sequencer_block_replay_server_address`         | HTTP replay removed, replaced by P2P                |
| `prover_api_object_store_file_backed_base_path` | ENs no longer use proof storage                     |
| `prover_api_object_store_mode`                  | ENs no longer use proof storage                     |
| `l1_sender_pubdata_mode`                        | ENs must not set this — inherited from main node    |

## Renamed Variables

| Old                   | New                   | Notes                                                                                                                |
|-----------------------|-----------------------|----------------------------------------------------------------------------------------------------------------------|
| `general_l1_rpc_url`  | `l1_provider_rpc_url` | Config key renamed. The `GENERAL_L1_RPC_URL` env var is unchanged — it's still mapped to this key in docker-compose. |

## New Required Variables

These config keys are required by the binary itself. If you run docker-compose directly, you must set them explicitly — there is no default. If you use `./external-node.sh`, it fills in `network_secret_key` (auto-generated) and `network_boot_nodes` (network default) for you when omitted; see steps 6 and 9 below.

```bash
# Node identity — tells the binary it is an EN
general_node_role=external

# P2P network — replaces HTTP replay
network_enabled=true
network_secret_key=<64-char-hex>     # unique per node; generate: openssl rand -hex 32
network_boot_nodes=<enode-urls>      # provided by ADI

# Optional
network_port=3060                    # default: 3060
```

## Changed Defaults

| Variable                                     | v0.13.0 default | v0.20.12 default | Action                                   |
|----------------------------------------------|-----------------|------------------|------------------------------------------|
| `observability_log_format`                   | `terminal`      | **`json`**       | Set `terminal` if you want readable logs |
| `observability_log_use_color`                | `true`          | **`false`**      | Set `true` for local dev                 |
| `sequencer_revm_consistency_checker_enabled` | `false`         | **`true`**       | Set `false` for faster local startup     |

## Port Changes

| Port  | v0.13.0  | v0.20.12         | Notes                     |
|-------|----------|------------------|---------------------------|
| 3050  | Open     | Open             | JSON-RPC (unchanged)      |
| 3054  | Open     | **Close**        | Old HTTP replay — removed |
| 3060  | —        | **Open TCP+UDP** | P2P devp2p (new)          |
| 3071  | Open     | Open             | Health/status (unchanged) |
| 3312  | Open     | Open             | Prometheus (unchanged)    |

## Other Changes

**Proof-sync sidecar** — remove it from docker-compose entirely. ENs no longer use proofs at all.

**Cloudflare replay proxy** — remove the `cloudflared-tcp-proxy` service from docker-compose. The HTTP replay transport it forwarded no longer exists.

**Genesis file** — replace with updated version that has `execution_version` field removed.

**Two coordinated network upgrades** — all cluster nodes must be upgraded together:
- Nodes on different versions will not peer with each other
- Batch verification transport is incompatible between versions

## Upgrade Steps

### 1. Confirm Main Node is Upgraded First

Wait for an official announcement from the ADI that the main node has been upgraded to v0.20.12 before upgrading your external node. Upgrading early will leave your node unable to peer or sync (see "Two coordinated network upgrades" above).

### 2. Stop the External Node

```bash
./external-node.sh down
./external-node.sh status    # confirm all stopped
```

### 3. Remove Proof-Sync Sidecar and Cloudflare Proxy

Delete the `proof-sync` and `cloudflared-tcp-proxy` containers from your docker-compose. ENs no longer use proofs and the HTTP replay transport is gone.

### 4. Pull Latest Repository Changes

```bash
git pull origin main
```

This updates the docker-compose file and `genesis/` for the network you're upgrading with the v0.20.12 configuration.

### 5. Remove Deleted Variables

From your config or `.env`:

```bash
sequencer_block_replay_download_address
sequencer_block_replay_server_address
prover_api_object_store_file_backed_base_path
prover_api_object_store_mode
l1_sender_pubdata_mode
```

### 6. Prepare Your Network Secret Key

This upgrade introduces P2P networking, which requires a unique secret key per node (`network_secret_key` / `EXTERNAL_NETWORK_SECRET_KEY`). You don't need to generate one yourself — if you don't provide one, `./external-node.sh` generates it automatically on first start and prints it to the logs:

```
[...] EXTERNAL_NETWORK_SECRET_KEY not provided — generated automatically: <64-hex-chars>
[...] Save this key and reuse it on restarts to keep your P2P node identity stable.
```

> [!CAUTION]
> **Save the private key securely.** If you lose it, you'll need to restart the node with a new key and resync it from scratch. You'll pass it explicitly on subsequent starts (see step 9).
If you'd rather generate one yourself ahead of time:

```bash
openssl rand -hex 32
```

> If you run docker-compose directly (without the script), the key must be set explicitly — there is no default.

### 7. Update Port Mappings

```
Remove: 3054 (HTTP replay)
Add:    3060/tcp + 3060/udp (P2P)
```

### 8. Pull the New Docker Image

```bash
./external-node.sh pull
```

### 9. Start the External Node

`GENERAL_L1_RPC_URL` / `--l1-rpc-url` is the only value you need to provide. `BOOT_NODE_URLS` / `--boot-node-urls` falls back to the network default if omitted.

#### First Start

If you haven't generated a key yet (step 6), just start the node — the script generates one and prints it to the logs:

```bash
./external-node.sh start --l1-rpc-url https://your-l1-endpoint
```

#### Subsequent Starts / Restarts

Pass the saved key explicitly so your node keeps the same P2P identity:

```bash
./external-node.sh start \
  --l1-rpc-url https://your-l1-endpoint \
  --external-network-secret-key <saved-key>
```

Or export it as an environment variable before running the script:

```bash
export EXTERNAL_NETWORK_SECRET_KEY="<saved-key>"
./external-node.sh start --l1-rpc-url https://your-l1-endpoint
```

To override the boot node default, add `--boot-node-urls "enode://<nodeID>@<ip>:3060"` (or the equivalent `BOOT_NODE_URLS` env var).

### 10. Verify Sync

```bash
./external-node.sh logs
```

Look for:
```
resolved external IP (STUN)    ← P2P networking works
Connected to peer <enode-id>   ← peers discovered
Replayed block #N              ← syncing
```

Should NOT see:
```
verifier authorization failures
missing VerifyBatchResult
```

Health check:

```bash
curl http://localhost:3071/status/health
```

Block number parity with main node:

```bash
# Your EN
curl -s -X POST http://localhost:3050 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'

# Mainnet reference
curl -s -X POST https://rpc.adifoundation.ai \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'
```
